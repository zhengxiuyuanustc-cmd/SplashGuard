# 同类工具对比与可借鉴设计

核验日期：2026-10-25。**实施状态已于2026-10-26更新，先看[推进清单实际状态](IMPLEMENTATION_STATUS.md)**；下文保留研究当天的资料及建议语境。研究范围是作者/官方公开文档和可审查源码，没有下载安装竞品，也没有做同条件实机跳过率、误触率或耗电测试。下列“建议”是面向开屏清净的设计推论，不代表竞品已有同样的安全保证。

## 最优先：明确区分节点动作与坐标手势

GKD为节点动作和坐标点击提供不同配置，官方说明后者被遮挡时可能触发上层控件；默认组合动作有坐标回退。其[动作说明](https://gkd.li/api/interfaces/rawruleprops)和[固定版本实现](https://github.com/gkd-kit/gkd/blob/fe6736fb083ba90d7bace124e30b61ff6e5701f2/gkd-app/src/androidMain/kotlin/li/gkd/app/data/GkdAction.kt)支持这种区分。

我们的建议：

- 新规则默认只允许节点动作；节点动作无效时不自动升级成坐标试点。
- 手势兼容只作为有真实正反例验证的应用/版本/组件特例，独立标记与审查；不能因为“可点击”或ID像skip就放行。
- 保留0.1.8的冲突拒点。规则更具体后仍不能在真假不明时按评分选一个，也不能逐个点击试错。
- B站历史兼容依赖过手势，因此不能在未复测时直接宣称收紧动作方式不会影响跳过率。

研究当天此方案尚未实现；后续已接入动作分离和提交前复核，见状态表。当时本地0.1.8只有冲突、可知的不完整扫描及重试键变化拒点，现有唯一候选的手势兼容路径仍在。

## 用小型结构化规则表达上下文

借鉴GKD将定位与场景分开的设计，先做受限字段，无需立即移植完整选择器语言。建议每条规则包含：

| 字段类别 | 建议内容 |
| --- | --- |
| 来源与版本 | 规则ID、规则版本、维护者、变更原因、验证日期 |
| 应用限定 | 精确包名、已验证的目标应用版本范围 |
| 场景限定 | 已验证的开屏容器、窗口或页面线索；不为取得页面字段默认新增高权限 |
| 目标关系 | 按钮标识/标签/类名、父层级及必要相邻证据 |
| 排除条件 | 针对目标与其上下文的危险语义/结构；避免因整幅广告有“下载”就一律误判 |
| 动作方式 | 节点动作，或经单独审核的手势兼容特例 |
| 验证样本 | 真按钮、假按钮、同ID伪装、错误父容器、普通内容页等脱敏正反例 |

目标应用升级超出已验证范围时，显示“待验证”，不让旧规则无条件覆盖新布局。所有字段仍是匹配线索，不能包装成系统认证。

GKD还提供执行顺序依赖，适合有前后关系的多步流程。[规则字段](https://gkd.li/api/interfaces/rawruleprops)可作设计参考。若未来研究应用内广告，必须使用独立、自愿启用的场景状态机，不把普通确认、授权、登录或付款操作纳入通用自动化；当前开屏规则不因此扩大范围，见[研究路线](ROADMAP.md)。

## 预算已有，后续规则包不能越过它

GKD提供匹配时段、次数、延迟复查及跨规则共享预算等字段。[生命周期说明](https://gkd.li/api/interfaces/rawcommonprops)

开屏清净已经有每次开屏12秒、最多两轮的共享会话预算，不能把这一点重复算作待新增能力。后续数据规则只能收紧预算，不能延长或重置硬限制。可以研究动作前短暂等待后重新确认同一目标是否仍唯一、可见且符合场景，缓解界面变化；稳定多帧仍不证明按钮语义真实。

## 规则社区可借鉴，联网和复杂配置不必成为默认门槛

GKD本地和远程规则使用统一订阅格式；当前官方README说明默认不提供规则。[订阅格式](https://gkd.li/guide/subscription)、[固定版本README](https://github.com/gkd-kit/gkd/blob/fe6736fb083ba90d7bace124e30b61ff6e5701f2/README.md)

适合本项目的方式是少量经过审核的内置规则作为默认，高级设置中才提供手动导入：

1. 贡献者通过Issue/PR提交规则和脱敏正反例，由维护者审阅。
2. 规则随APK更新，或用户从网站下载离线数据包后手动导入；App继续不申请INTERNET。
3. 导入前校验格式、来源/签名、版本、文件大小和硬预算，不接受任意脚本或任意页面操作。
4. 显示这次增加/停用了什么，允许撤销导入和恢复内置规则。来源签名不等于规则一定正确，仍需审查与实测。

签名、回滚和本项目的有限字段方案是本报告建议，并非已核实GKD提供同样保证。研究当天这些功能尚未实现；目前已有收紧限制包、暂停和撤销，但来源验签与新增匹配条件包仍未实现，不能混称完成。

## 复现偶发问题：最小脱敏样本，而非默认上传完整页面

GKD的快照与审查工具能关联界面和节点，官方文档也提醒公开分享及脱敏的影响。[快照说明](https://gkd.li/guide/snapshot)

本项目建议先做用户主动触发的最小诊断导出：目标版本、规则ID、固定失败原因、必要控件关系与边界；默认不截图、不导出整页文字、不上传。导出前让用户预览和删除内容。提供离线回放检查，开发者无需等待同款广告再次投放，也能检验规则是否误选。

动作提交记录与真正关闭广告的观察应分开。正常首页/广告容器退出的结果确认需按应用单独验证；按钮消失或系统动作回调都不能直接计作成功。

## 后台与用户设置：借鉴具体教程和可见状态

轻启动作者站有标注系统版本的[MIUI 14指南](https://wpengapp.com/romsetting/bg?appLogo=http%3A%2F%2Fwpengapp.com%2Fres%2Fimage%2Fwpengapp%2Fapplogo%2Flogo_light_start.png&appName=%E8%BD%BB%E5%90%AF%E5%8A%A8&brand=XIAOMI)和[OneUI 5指南](https://wpengapp.com/romsetting/bg?appLogo=http%3A%2F%2Fwpengapp.com%2Fres%2Fimage%2Fwpengapp%2Fapplogo%2Flogo_light_start.png&appName=%E8%BD%BB%E5%90%AF%E5%8A%A8&brand=SAMSUNG)，且可手动修正品牌。GKD FAQ提供后台设置和耗电影响因素说明。[GKD FAQ](https://gkd.li/guide/faq)

我们应把现有机型指南补成“品牌＋型号＋系统版本＋核验日期＋图片步骤”，无法自动配置时转手动指引。首页明确服务连接、功能启用、应用选择三个状态；提供“暂停这个应用”与简便恢复入口。若未来加入可选通知，应单独说明授权和关闭方式，不用通知存在暗示永不被系统停止。

配置备份可参考轻启动历史版本中的思路，但优先手动本地导出。只恢复本工具配置，不能把导入文件视为系统无障碍已授权、后台管理已设置或B站原生广告开关已关闭，恢复后仍需核对。

## 不适合作为默认方案的部分

- 轻启动[历史日志](https://wpengapp.com/lightstart/v)记录过可选坐标、Xposed、设备管理员、云备份等功能，并注明部分兼容或卸载影响。它们不适合作为本项目面向普通用户的默认路径，也不能据历史日志断言当前包仍具有这些功能。
- GKD被检查的[公共Manifest](https://github.com/gkd-kit/gkd/blob/fe6736fb083ba90d7bace124e30b61ff6e5701f2/gkd-android/src/main/AndroidManifest.xml)声明INTERNET及多项扩展能力。不能把“核心可离线”与“安装包无网络权限”混为一谈；本项目不为对齐功能数量增加权限。
- 保留正常方向、导航和体感能力。各类辅助点击不能等同系统级防摇一摇拦截，本项目仍优先提供应用自己的广告专用设置引导。
- GKD[源码许可证](https://github.com/gkd-kit/gkd/blob/fe6736fb083ba90d7bace124e30b61ff6e5701f2/LICENSE)标注GPL-3.0-only。本次借鉴设计；如要引入代码或第三方规则，须逐项核对许可与来源，不能原样作为本项目MIT代码处理。

## 建议的实施顺序与验收

| 优先级 | 工作 | 验收要点 |
| --- | --- | --- |
| P0 | 节点/手势策略分离，审查已有坐标兜底 | 假覆盖层、不响应的节点、目标变化时不盲点；B站已有兼容场景单独复测 |
| P0 | 版本/容器/排除条件的有限规则结构 | 真/假顺序交换、相同ID/边界、错误父层级及普通页面均有正反例；未知版本状态明确 |
| P1 | 用户主动的最小样本导出和离线回放 | 默认无截图/上传；可预览脱敏；同一夹具可重复验证 |
| P1 | 离线规则包、单条停用、导入撤销 | 不能突破硬预算或包名范围；恢复规则不重置应用选择和系统权限 |
| P1 | 分机型图文教程与可选本地备份 | 型号识别错误可修正，历史路径标版本，能暂停/恢复且没有账号门槛 |
| 持续 | 标准构建、正式发布与实机矩阵 | 目前SDK构建通过不等于Gradle通过；调试预览包不当正式稳定版发布 |

对测时每次只启用一套辅助工具，以免混淆动作归属。先用受控真假按钮夹具，再进行真实广告观察；沿用用户已验证的清后台、熄屏、解锁、重开步骤，但未出现广告应单独记为缺少样本。记录实际误触、明确跳过、保守拒点、耗时和后台状态，不用动作计数冒充跳过率，也不凭宣传排竞品名次。

研究阶段只形成建议；后续实现见状态表。始终没有导入竞品代码/订阅或把历史对比写成实机跳过率；公开APK的状态另见TESTING。
