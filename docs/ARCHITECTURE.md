# 架构与数据流

本文描述本地0.1.9构建候选，尚未公开发布；网站0.1.7不含新增规则文件和帮助工具。当前范围是所选应用的短暂开屏广告辅助处理，以及广告专用设置的手动引导。应用内持续广告跳过仍是独立研究方向，见[路线图](ROADMAP.md)。

```mermaid
flowchart TD
    U[用户选择应用并开启功能] --> P[Prefs 本地设置]
    E[无障碍事件或亮屏事件] --> S[SkipService 合并扫描请求]
    S --> G{已启用且手机已解锁?}
    G -->|是| F[读取前台根节点并判断包名]
    F --> T[SkipSession 有限会话]
    T --> A{选中应用且仍在12秒开屏时段?}
    A -->|是| R[AdRules 精确文字/标识/场景/边界]
    R --> M[有限版本/目标/实际祖先与排除判断]
    M --> Q[完整扫描后收齐候选并判断唯一性]
    Q --> O[本地限制与ActionPolicy门控]
    O --> C[默认控件动作 / 显式已验证兼容手势]
    C --> V[复查原目标与有限重试]
    V --> L[Prefs 少量本地操作记录]
```

这张图描述的是处理流程，不是无障碍授权范围的隔离承诺。Android 无障碍权限允许读取界面控件和模拟点击；服务会先读取活动窗口根节点及包名，再判断是否为用户所选应用。不能宣传为“权限层面只能看到所选应用”。

## 组件职责

| 组件 | 职责 |
| --- | --- |
| `MainActivity` | 首页、防摇一摇、设置三分区；真实状态、权限说明、应用选择和手动设置引导 |
| `OnboardingPolicy` | 首次安装、旧用户迁移、未完成向导恢复及步骤边界的纯逻辑 |
| `SkipService` | 监听事件、合并扫描、检查屏幕/前台环境、取得节点、提交动作并处理异步回调 |
| `SkipSession` | 与 Android UI 无关的会话状态机、截止时间、动作预算及过期回调隔离 |
| `AdRules` | 与 Android API 无关的文本、精确资源标识、场景及边界判断 |
| `CandidateSelection` | 按真实节点身份去重及全集唯一性，不凭相同ID/文字/边界合并不同节点 |
| `RuleSpec` / `RuleEvaluator` | 编译期可信的有限包名/版本/目标/父链/实际祖先/排除条件 |
| `RuleCatalog` / `RuleRuntime` | 内置目录、已知B站目标隔离与运行时限制门控，不能靠通用规则绕过 |
| `ActionPolicy` | 控件动作与经过验证的兼容手势许可分离；普通规则永不自动回退为坐标 |
| `OfflineRuleStore` / `RuleJsonCodec` | 外部数据只收紧已有规则；严格解析、一步撤销，不解释执行代码 |
| `RuleData` | Android私有偏好持久化、损坏状态拒点、内存最小样本 |
| `DiagnosticSample` | 固定枚举/数值/布尔的判定输入与离线复核，不重建屏幕或执行点击 |
| `SetupHelpActivity` / `DeviceGuidePolicy` | 状态自检、品牌/系统分流、用户主动复制摘要 |
| `OfflineToolsActivity` | 用户明确预览/应用文件、撤销/恢复与高级兼容设置 |
| `Prefs` | 手机本地的开关、应用选择和少量操作/诊断记录 |

## 从事件到点击

1. 服务收到事件后合并短延迟扫描，避免动画事件持续把扫描推迟。只有功能已启用时才排队处理。
2. 手机非交互或锁屏时不取得活动窗口根节点，必要时重置会话。熄屏会重置；亮屏和解锁只请求检查，不凭这些事件延长已有会话。
3. 获取前台包名后通知会话状态机。随后检查所选应用、排除工具自己，并检查 12 秒处理窗口。页面暂时缺失或同应用事件不能无期限续命。
4. 要求目标应用接近全屏，候选控件可见、启用、包名一致、完全位于窗口和屏幕范围内。深度和节点数量也有上限。
5. 先收集场景证据，用精确规则筛选控件并核对候选的真实祖先；完整扫描后收齐所有候选，两个不同节点或扫描不完整即停止。详见[规则指南](RULES.md)。
6. 默认只尝试候选本身的`ACTION_CLICK`，删除旧版向近层父控件逐级回退的路径。普通规则被拒、不可点击或第二轮重试均不自动获得手势许可。仅版本名称9.15.0、实际祖先与其他门控满足、规则仍允许且用户另外开启兼容时，可提交来自当前候选边界的精确短手势。
7. 每次真正提交前重新取得当前窗口并完整扫描候选全集，核对同一原节点身份、窗口、边界、版本与规则，再刷新目标并复核当前前台、解锁、选择、限制及期限。原节点动作返回失败后本轮结束，不立即对旧坐标补手势；兼容重试只能在后轮重新检查。随后复查原候选，并在预算内进行有限重试。最多两轮处理、最多两次被系统接受的动作；首轮被拒绝的控件调用与受限回退不应被错误描述为所有 Android API 总调用数最多两次。
8. 回调携带会话epoch/operation token；换应用、锁屏、会话过期或关闭功能后，旧回调不得重新激活处理或重复计数。多候选/不完整扫描、规则或兼容设置改变时停止当前会话但保留包名、原截止时间及预算，不因下一帧事件重新开窗。

跨进程读取无法形成绝对原子的画面快照；最后检查后仍可能发生页面变化，不能因此保证零误触。

“动作被接受”与“广告已经消失”不同。当前计数反映操作提交记录；真实效果需要观察页面是否提前结束。扫描结束后的有限复查也不能代替对所有广告素材的实机验证。

## 首次设置与 Activity 生命周期

五步向导依次介绍用途和权限、选择应用、本人开启无障碍、核对防摇一摇/后台设置、检查实际状态。每步可稍后设置；完成向导不会自动授权或开启功能。

持久化键为 `onboarding_seen`、`setup_in_progress`、`setup_step`。已有 `enabled`、`apps`、`count` 或 `last_time` 的旧用户不被强制重新引导；进行中的向导优先恢复，因此选择应用后不会被误当作旧用户跳出。用户可在设置中主动重开向导。

`onResume` 仅更新当前状态，不重新生成整页。页签、折叠与滚动位置保留在 Activity 状态中；引导步骤还保存在本地偏好中，支持流程中返回系统设置。更新 UI 时不要退回每次 `onResume` 直接重建页面的做法。

## 本地规则和用户文件

`RuleCatalog`随APK提供可信匹配定义。`OfflineRuleStore`的导入文件只能收紧现有目录与当前状态；JSON不接受选择器、正则、脚本、新规则或新包名。目录中的`@selected`仅标记通用规则沿用用户选择，服务仍需先检查`Prefs.selected`，不是全应用通配。

`RuleData`一起持久保存当前/前一步快照和撤销标记，损坏时拒绝处理，不静默放宽；规则导入失败无副作用，撤销只有一步，恢复内置不改其他功能设置或系统权限。规则变动监听不会被操作计数/普通诊断写入触发而反复重置会话。

`DiagnosticSample`只在内存保留最后一份固定字段。文件导出需预览及系统文件选择；导入后的复核不读取屏幕、不执行动作。设置帮助的主动复制摘要另外包含机型与少量应用版本，不能混称同一种数据。详见[离线工具](OFFLINE_RULES.md)和[隐私说明](../PRIVACY.md)。

## 防摇一摇的准确含义

本工具提供应用内广告专用设置的指引。已核对的B站 9.15.0 路径是“我的 → 设置 → 隐私权限设置 → 允许广告访问传感器：关闭”；状态由B站保存，工具不能把阅读指引当作已关闭。

没有全局关闭加速度计或设备方向感应，不使用 VPN、Root 或系统权限劫持。正常旋转和体感所需的整体权限保持原样；自动跳过只是尽早结束广告，广告结束前仍可能触发跳转。不能声称所有应用的晃动跳转都已被阻断。

## 隐私与信任边界

App 没有 `INTERNET` 权限，识别在本机进行，不上传界面、所选应用或设备信息；不请求设备唯一标识。控件文字在识别过程中被临时读取，不能笼统写“从不读取用户内容”。

本地保存 `enabled`、`apps`、计数 `count`、最近应用/按钮 `last`、时间 `last_time`、少量 `diagnostic` 及引导状态。清除操作记录时移除 `count`、`last`、`last_time`、`diagnostic` 和兼容性诊断时间键 `last_diag_time`，保留功能选择、引导及规则状态；同时清除进程内最小样本，不替用户删除已经导出的文件或剪贴板。当前服务只写 `diagnostic`，并未持久化该兼容时间键。

网站、GitHub 反馈和打赏由系统浏览器及相应平台处理，属于另一个联网边界。给 App 增加统计、远程规则、网络 SDK 或新敏感权限均须作为独立设计变更说明，不得悄然加入。
