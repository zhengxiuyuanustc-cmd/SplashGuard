# 离线规则来源验签（0.1.14候选）

2026-10-27：候选代码和本地SDK 35未签名构建已完成；21个纯Java程序1645项通过。本次标准debug/未签名release、双lint与纯Java CI均已通过，已生成本地签名测试包；手机文件选择器、旋转/进程重建、真实磁盘故障及真实广告仍未验收。发行与构建证据见[验证记录](../TESTING.md)，协议细节见[设计边界](OFFLINE_RULE_AUTH_DESIGN.md)。

## 普通使用不需要导入

内置开屏规则已随App提供，日常使用无需下载规则文件。离线文件只能进一步限制已有规则，例如缩短识别时段、减少次数、限制版本或停用；不能新增应用、选择器、脚本、点击位置或联网更新。0.1.13开始暂停的坐标触点不会被签名文件重新打开，也不会关闭正常方向传感器。

“发布者签名已验证”只说明原始输入通过内置信任公钥验证；不证明规则正确、按钮真实、无障碍权限可用或广告已关闭。当前有效快照可能合并此前的本地限制，不能把它整体称为发布者签过的文件。

## 自愿选择、预览、确认

1. 在App“设置”中打开“离线规则与诊断”，点击“选择作者签名文件（先预览）”。
2. 通过系统文件选择器选择完整`.jws`文件。文件格式和签名通过后，还要检查当前限制和该渠道历史。预览显示发布者、渠道、密钥编号、限制包及版本；此时没有应用。
3. 阅读具体限制后，点击“确认应用预览中的限制”。App重新验证内存中的同一原始文件，并重新读取当前状态；保存确认后才生效。拒绝或保存未确认均不会显示应用成功。

此路径不会自动下载、上传或取网络公钥，也不增加联网或存储权限。系统文件选择器若指向云盘，云盘行为由对应服务负责。普通JSON限制应走“选择普通本地限制（未认证）”，不会获得可信发布者标记。

原始文件和预览只保留在当前进程内存；候选代码支持旋转时保留任务，但进程重建后必须重新选择。保存状态的`Bundle`不包含签名原件或Pack，不会靠恢复一个解析结果重建认证。系统DocumentsUI和Activity.recreate已在API26/35/37隔离模拟器验收；厂商文件提供者、实际旋转/大字体及进程被杀仍待设备验证。

## 信任来源与文件边界

当前[内置映射](../app/src/main/java/org/splashguard/app/RuleTrust.java)固定如下；文件不能替换它：

| 字段 | 当前值 |
| --- | --- |
| 发布者 / 渠道 | `splashguard` / `community` |
| 密钥编号 | `splashguard.rules.20261027` |
| 允许的Pack ID | `splashguard.community` |
| 公钥 | 独立RSA 3072位，SPKI SHA-256 `b5754754ab983e6f8dacd8c5965390169df08f891c10d8ef911339851cdaa43e` |

公开参数见[rule-authority.json](../tools/rule-authority.json)。可信映射只随审阅后的App代码更新；导入文件不能携带新公钥、URL取钥地址或自定义渠道。一般验签器接受受审配置中的RSA 2048—4096位、公开指数65537；当前发行候选使用上表独立密钥。APK升级签名密钥不参与规则签名。

文件采用受限JWS Compact：恰好三段规范无补位base64url，只接受`RS256`，头仅有`alg`、`kid`、`typ`，其中`typ`为`splashguard-rule-limits+jws`。总计最多65536字节，解码头最多256字节、载荷最多48000字节；拒绝外层空白、换行、BOM、重复/多余字段及非规范编码。载荷是严格UTF-8的现有Pack JSON，之后仍执行内置/当前限制校验。

摘要计算的是解码后**原始载荷字节的SHA-256**。调整JSON缩进、换行或字段顺序，即使解析后的限制相同，也会得到不同摘要；不得把格式整理后的内容当作同一版本重发。

## 版本历史和恢复

每个可信发布者/渠道维护独立最高版本及该版本的原始载荷摘要，最多16个渠道。当前只编译上表一个渠道。更换Pack ID、本地暂停、普通JSON导入、撤销和恢复内置，都不能清除这份历史。

| 所选可信文件 | 处理 |
| --- | --- |
| 低于已接受最高版本 | 拒绝 |
| 相同版本、不同原始载荷摘要 | 拒绝 |
| 相同版本、相同摘要 | 提示已接收，不重新应用，不改变有效限制和撤销记录 |
| 更高版本 | 限制仍须收紧；保存确认后才能推进历史 |

因此，撤销、恢复内置或正常重新读取完整保存状态后，再选同一已接收文件不会重新应用它。本地未认证文件即使冒用相同Pack ID和极大版本，也不能污染可信渠道修订；可信更新仍不能放宽当前限制。

当前限制、上一步快照、撤销标志、来源及账本写入同一状态JSON，连同认证暂停和隔离标记在同一个同步保存事务提交。Android官方文档说明，`commit()`原子应用本次编辑、同步写入持久存储，并通过返回值报告保存是否成功；这不是本项目已完成真实磁盘故障验收的证据。[SharedPreferences.Editor.commit](https://developer.android.com/reference/android/content/SharedPreferences.Editor#commit())

提交失败会触发本进程故障闩，停止普通处理；只有明确恢复且保存成功才解除。恢复保留实际可读、可验证的最高历史，不能把失败提交可能已经变化的后端内存视为“必然未发生”。

状态损坏时可明确恢复内置规则以恢复基本使用，但损坏记录会隔离，**签名导入继续暂停**，不会静默清空历史后当作第一次导入。纯内存后端故障检查覆盖这些分支，隔离模拟器还通过了私有目录只读导致的真实提交失败恢复；这不覆盖全部磁盘故障、进程死亡、重启或厂商存储提供者。详见[模拟器验收](ANDROID_EMULATOR_ACCEPTANCE.md)。

这不是绝对防回退：清除App数据、卸载重装、回滚私有存储及高权限篡改不在保证内；离线App也不能保证用户已拿到最新文件或即时撤销信息。

## 示例和作者工具

[公开示例](../examples/offline-rules/README.md)只演示认证一个现有通用规则上限的部分载荷；不新增识别器，不建议日常用户为“升级效果”导入。已有更严格限制时可能拒绝；初次确认会记录渠道版本1并改变撤销记录。

[作者签名工具](../tools/sign-rule-pack.ps1)仅供持有独立规则私钥的维护者使用，要求Windows和PowerShell 7.6以上，已在7.6.5验证。私钥采用DPAPI CurrentUser封装且留在忽略目录；工具核对公开配置和公钥指纹，对原始载荷字节签名，以CreateNew创建输出，拒绝覆盖文件；不操作手机、不联网。该工具的基础JSON检查不替代Android导入器的严格解析和当前限制校验，签名成功不等于App必然接受。

贡献者无需获取作者私钥。新的选择器、允许包范围或信任根变更仍应通过源码PR审查；已签名文件不能绕过这条边界。
