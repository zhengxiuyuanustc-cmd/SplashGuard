# 0.1.17：B站后台漏过的诊断增强候选

2026-10-30，用户进一步明确：初次启动可自动跳过，主要问题是保留B站后台后再次打开。0.1.16在本机自动启动方式的多次京东/天猫广告提前退出；用户手动返回时，一次动画宣传页从跳过5播至0，服务在前后都保持连接。该失败已复现，不能用其他素材通过宣布解决。原始画面不公开。

## 此次实现

- 最近识别会话同时保留最后状态和最近具体判定。普通未匹配/时段结束不再覆盖更有用的拒绝原因或动作提交状态；新选中应用会话明确清除旧线索。只保留两个内存快照，不新增持久日志。
- 页面显示本进程中最近识别会话的相对年龄，帮助发现旧会话没有重新开始；这不是对本次广告进入时间的认证，不导出绝对时间或设备标识。
- 本人主动准备的两分钟等待/十二秒采样，即使旧点击时段结束仍可只读记录有限节点；不重新开启点击、不消耗或重置动作预算。
- 原生动画宣传资源里存在另一组skip/root标识。此次只将它们加入固定脱敏诊断词表，允许采样保留其身份；没有加入自动点击规则。运行时父层级、场景及具体拒绝仍需失败样本确认。
- 重新准备或当前没有夹具时清除旧预览，并禁用旧文件导出，防止把先前成功帧当作新失败帧。

## 当前未解决的事项

失败后只取得最终WINDOW_EXPIRED，不能据此断定广告一出现时已过期，早先拒绝可能被覆盖。首轮手机控件采样比电脑画面观察提前到期，已把电脑等待改成110秒，后续一次未出现广告只记未知。安装包资源分析发现不同布局是线索，并非失败现场的运行时节点证据。独立静态检查曾临时暂停功能，仅取得商业count_down路径；暂停期不计为失败行为，之后已恢复启用并确认服务绑定。

0.1.17目前是诊断增强候选，不是已证明解决后台推广的修复版。保留既有版本/祖先/唯一候选/提交前复核、12秒/两次动作、坐标暂停和无网络权限。未改RuleCatalog/AdRules的动作选择器；不以扩大搜索或盲点换取跳过率。构建与隔离验收已完成，签名候选已在本机安装回读一致、服务已绑定且首页就绪；之后需取得实际后台失败帧来决定下一项有证据的规则修正。
