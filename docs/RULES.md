# 为识别规则提交可审查的证据

0.1.14的[作者验签](OFFLINE_RULE_AUTH.md)仅认证现有槽的限制输入，不是动态新选择器接口。新识别规则仍须源码PR、正反例与相应验收；签名不认证按钮真假。

公开0.1.7的规则入口是`AdRules.java`，会话约束是`SkipSession.java`。当前0.1.13候选沿用`RuleSpec`/`RuleEvaluator`/`RuleCatalog`/`RuleRuntime`与`ActionPolicy`的有限规则及动作门控；服务提交动作之前仍检查前台、解锁、包名和窗口条件。规则贡献不是“尽量多点几个地方”，而是为一个明确场景增加能解释、能测试的判断。

## 先确认问题类别

- 没出现广告：无法据此验证跳过成功，请按“未出现广告”记录。
- 服务未连接、应用未选择或功能开关关闭：先修复设置与状态，通常不需要放宽规则。
- 广告已出现，控件符合预期但动作未生效：检查点击结果、父控件或异步回调，不要立即增加匹配范围。
- 开屏时段外的应用内广告：当前不支持，请转到[应用内广告研究](ROADMAP.md)，不要直接延长 12 秒预算。

## 当前匹配边界

当前0.1.13候选继承多候选冲突与扫描不完整拒点；任一潜在线索祖先不完整也让整帧停止。通用规则要求完整同包祖先，已识别WebView暂不支持。SDK标识只接受已有8个精确名称，不再匹配任意子串；动作仅限控件本身。此改动不等于真假认证，唯一假节点仍可能漏检；原理、影响及待验证场景见[真假按钮策略](FAKE_BUTTONS.md)。公开0.1.7包不包含这些新增保护。

通用候选位于右上区域，并有尺寸上限。明确“跳过广告 / 关闭广告 / skip ad”等标签与“跳过 / skip”加广告证据、倒计时、特定 splash SDK 标识的路径不同。某个词在单元测试中命中，不表示可以脱离服务的开屏会话或窗口检查直接点击。

B站规则额外要求精确包名 `tv.danmaku.bili`、已知开屏容器或类名，以及明确的跳过控件 ID 和标签。9.15.0 的控件可以出现在右下角，因此使用特定场景规则，不把所有应用的通用点击区域扩到页面底部。

当前一个已收录样本是：

```json
{
  "app_version": "9.15.0",
  "screen": [0, 0, 1200, 2652],
  "scene": {"id": "tv.danmaku.bili:id/splash_layout", "class": "android.widget.FrameLayout"},
  "skip": {"id": "tv.danmaku.bili:id/count_down", "class": "android.widget.TextView", "text": "跳过5", "bounds": [868, 2425, 1148, 2565]}
}
```

完整过滤样本见 [`tests/fixtures/bilibili-9.15.0-tmall-splash-layout.json`](../tests/fixtures/bilibili-9.15.0-tmall-splash-layout.json)。数值描述这一次样本，不是可直接复制到其他手机的固定点击坐标。

## 有限规则与动作许可分开

0.1.9候选的可信内置规则可限定精确包名、数字版本码范围、版本名称、目标模式、从直接父节点开始的父链、目标实际祖先容器及排除条件。父链和容器只看**该候选的真实祖先**，整页其他地方出现相同标记不能代替。祖先读取不完整时不能将它视为匹配。正则仅是可信源码中的常量，不暴露给外部JSON。

B站历史证据仅记录版本名称9.15.0，没有可信数字版本码，不能为它编造版本码。相同ID与真实场景在其他版本可作为未验证的控件动作匹配，但不能获得坐标手势。已知B站目标被上下文/排除条件否决，或其规则被禁用、缩短时段/轮数后，不能退回通用规则绕过该限制。

默认动作是候选本身的控件点击，不再逐级寻找可点击父控件；这可能漏过仅父容器处理点击的布局，需用明确样本为独立动作目标建模。通用规则首次动作被拒、目标不可点击或第二轮重试，均不因此自动转坐标手势。0.1.13已暂停全部坐标触点，旧兼容值不能重新启用；旧B站特例只有名称范围，缺少维护中的可信数字版本和可靠遮挡校验，不能当作安全许可。服务手势能力声明同时关闭。规则命中和系统接受动作仍不等于广告已正确关闭。

运行时限制只能保持或收紧会话的12秒/两轮上限，不能续期。同包规则或兼容开关改变要废弃旧回调，保留原期限和已消耗预算，不能用reset重新赋予处理时段。所有已匹配节点仍先进入全集冲突判断，再过滤重试键或提交动作。

## 文件不是新规则执行入口

外部离线文件只可收紧内置目录中已有规则的版本码范围、时段、轮数与开关，不接受目标模式、父链、正则、脚本、额外包名或任意动作。目录变更须通过源码PR和相应正反例；不能把互联网上的选择器直接塞进用户文件。严格JSON格式、单步撤销和恢复语义见[离线规则与诊断](OFFLINE_RULES.md)。

最小规则样本导出只包含固定枚举/数值/布尔，与下文人工整理的布局fixture不同；它没有原始节点文字/ID/坐标，无法独立补齐新场景选择器。导入复核只能解释保守判定，不运行Android动作或证明真实广告关闭。

## 每条规则都要有正例与反例

正例至少说明：目标应用和版本、场景证据、明确跳过标签、精确标识、控件类型及相对屏幕位置。建议先加入会失败的回归检查，再实现最小规则，使同一检查通过。

反例至少包括与改动有关的几个方向：

| 反例 | 必须拒绝的原因 |
| --- | --- |
| 同标签位于普通内容页 | 没有受支持的广告场景或不在开屏会话 |
| 普通“×”“关闭”“下一步” | 可能属于内容、弹窗、导航或用户操作 |
| “允许”“同意”“下载”“安装”“领取”“打开” | 不是跳过广告的目标 |
| 错误包名、超大控件或越过窗口边界 | 目标与范围不可靠 |
| 相似 ID，但没有受支持的容器/标签组合 | 不能只凭一个模糊标识猜测 |
| 锁屏、过期会话、旧回调或已取消选择的应用 | 处理上下文已经失效 |

不要添加固定屏幕坐标、普通“×”泛匹配、无广告证据的任意关闭按钮、包名通配或页面常驻扫描。不要通过“匹配失败就点返回键”、自动确认权限或点击广告入口来提高计数。

## 脱敏样本怎么整理

只保留支撑规则的最小字段：应用/版本、广告场景标识、控件 ID、类名、标签、可见/启用状态、边界及屏幕尺寸。记录采样日期和限制，例如是否只覆盖部分节点、是否在诊断工具介入时取得。

不要提交完整界面树、账户页面、聊天内容、付款或授权信息、手机号、IMEI、设备序列号、PIN、调试凭据、原始广告跳转链接或完整手机日志。确需截图时先裁掉无关区域并遮盖个人信息；优先提交过滤后的 JSON。

`tests/fixtures/`根目录的历史过滤摘录仍供人工审阅，不能推断完整扫描或自动覆盖。`tests/fixtures/rule-replay/`另有可执行Schema 2合成帧与index.tsv，RuleReplayCorpusTest实际遍历索引并要求所有JSON登记，32份样本393项检查已接入统一脚本。新增场景须说明来源及合成前提、补充相应正反例；修改低层规则或运行预算仍应加入对应Java检查，不能只放未登记文件就宣称覆盖。

## 提交与验证

在 PR 中说明新支持的具体场景、修改前失败和修改后通过的结果，以及未验证的设备和素材。运行[纯 Java 检查](DEVELOPMENT.md)，并在条件允许时补实机结果。

实机结论区分“发现候选”“系统接受动作”“广告提前消失”“物理晃动未跳转”；测试一次广告不能推广为全机型或所有素材支持。真实样本暂未再次投放时，保留待复测状态。
